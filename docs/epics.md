# wms - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for wms, decomposing the requirements from the PRD, UX Design if it exists, and Architecture requirements into implementable stories.

## Requirements Inventory

### Functional Requirements

- **FR01:** Admin có thể sửa, khóa tài khoản và phân quyền chức năng cụ thể dựa trên ma trận RBAC.
- **FR02:** Hệ thống chứng thực đăng nhập qua chuẩn bảo mật JWT, điều hướng tính năng Navigation linh hoạt.
- **FR03:** Admin có thể lưu các biến Cấu hình Hệ thống (Tên chuẩn đơn vị đo lường, Form mẫu Excel Uploads).
- **FR04:** Phân quyền Users thao tác CRUD trên Category Sản phẩm, kèm thuộc tính lõi chiều dài quy chuẩn và khối lượng tiêu chuẩn.
- **FR05:** User thao tác quản trị thư viện Danh bạ Khách hàng và cấu trúc bảng Giá / Profile Chiết khấu cho họ.
- **FR06:** User có quyền được tạo bộ 3 phiếu: Nhập kho, Xuất Kho (assign theo Khách hàng và tình trạng công nợ sơ bộ) và Tách hàng từ cuộn chuẩn.
- **FR07:** Việc Xác nhận (Confirm) các trạng thái phiếu sẽ biến Data thành immutable, và Hệ thống kích hoạt module cấp Mã số Ticket ID thông minh tự động (như PN-0001, PX-0002).
- **FR08:** Engine Quy đổi gọi ngầm tự tính metric m², kg, cuộn lập tức lúc add item vào Line phiếu.
- **FR09:** Engine Định giá Auto-load bảng Rule của khách → map ra Disount Rate → Fill vào Field Price mà không báo lỗi nếu user đang offline giữa chừng.
- **FR10:** Database chỉ Update Stock Balance (mức lượng kho) lúc Phiếu "Confirmed".
- **FR11:** Mọi hành động tăng giảm Update Stock tạo rác log Insert-Only trong lịch sử (Audit Trail) phục vụ truy vết ai đã làm lúc mấy giờ trên phiếu xuất nào.
- **FR12:** Chặn Hard-Limit không cho xuất quá quota hiện tồn (Negative-Stock).
- **FR13:** Role cấp cao có thể Hủy/Sửa phiếu đã Xác nhận nhằm Trigger Audit Roll-back tồn kho ngược lại trạng thái cũ.
- **FR14:** Report Engine đẩy thông tin Real-time sang Excel Format và Native PDF (generated by Backend Puppeteer).

### NonFunctional Requirements

- **NFR1:** Performance/UI Grid - Bảng tồn kho có thể render trơn mượt vạn Record dưới thời lượng 1 giây nhờ virtual-rendering (pluto_grid).
- **NFR2:** Response Rates - Nhịp đập API tới NestJS khép kín dưới < 500 mili-seconds; App boot < 3s trên Windows PC phổ thông.
- **NFR3:** Numeric Lock/Data Integrity - Schema DB bắt bấp kiểu lưu Math là dạng NUMERIC(15,3) thay thế dạng float gốc code.
- **NFR4:** Security Integrity - Mật khẩu thiết kế Salt+Hash bằng thuật toán bcrypt, gói Token Auth được mã hóa sâu tại local hardware flutter_secure_storage. Mạng kết nối TLS/1.2 over HTTPS.
- **NFR5:** Workplace Ergonomic Usability/Navigation - Các Form nhập xuất được optimize để có thể chỉ dùng phím Tab và Enter hoặc key-bind như Ctrl+S mà bypass 90% thao tác chỏ chuột.
- **NFR6:** Always-Online Paradigm - Mất mạng màn hình sẽ bị khóa để ngăn dữ liệu sai lệch (half-synced state).

### Additional Requirements

- **Starter Template:** Official NestJS CLI (`@nestjs/cli` new) + Custom Clean Architecture. Cần file `docker-compose.yml` cho PostgreSQL 16 và Redis. Phải làm trong Epic 1 Story 1.
- **Frontend Architecture:** Flutter Desktop 3.x với Riverpod. Tách riêng repo.
- **Data Exchange Format:** Dữ liệu kiểu `NUMERIC(15,3)` phải được serialize bằng String qua JSON API. Flutter parser string thành kiểu `Decimal` custom.
- **Code Organization (Backend):** Áp dụng pattern thư mục: `domain`, `application`, `infrastructure`, `presentation`. Lớp `domain` bị cấm hoàn toàn NestJS/Prisma dependencies.
- **Exception/Error Handling:** Backend sử dụng Custom Exceptions và ExceptionFilter thành JSON với `errorCode`. Flutter nhận và điều phối qua Dio interceptors.

### UX Design Requirements

*(Không có UX Document chuyên biệt. System được chốt là dùng reference từ wireframes + Material 3, redesign scope được defer. Phần này để trống)*

- **FR10, FR11:** Epic 3, 4, 5 – Luồng cập nhật Data DB trên Confirm & Audit trail.
- **FR12:** Epic 4 – Chặn Negative-Stock ở luồng xuất.
- **FR13:** Epic 5 – Quyền Hủy/Sửa phiếu để Roll-back.
- **FR14:** Epic 6 – Puppeteer/ExcelJS report.

## Epic 1: Authentication & System Foundation

Admin và nhân viên có thể đăng nhập an toàn vào một không gian phân quyền rõ ràng; Admin dễ dàng khởi tạo các biến hệ thống để vận hành.

### Story 1.1: Secure JWT User Login

As a Staff Member,
I want to authenticate myself using a secure login screen,
So that I can access the warehouse management system safely.

**Acceptance Criteria:**

**Given** an initialized NestJS backend and Flutter desktop application
**When** the user submits valid credentials (email and password)
**Then** the backend validates the password using bcrypt and returns a JWT token
**And** the backend simultaneously generates a Refresh Token, safely hashed and stored in Redis under `session:refresh_token:{userId}`.
**And** the backend compiles the user's active permissions and stores the context in Redis under `session:user_data:{userId}`.
**And** the Flutter app securely stores the token and navigates to the main layout dashboard
**And** if the user is offline, the system blocks the login attempt and shows an error banner.

### Story 1.2: Identity Management & RBAC Enforcement

As an Admin,
I want to manage staff user accounts and assign specific roles,
So that I can strictly control who has access to sensitive warehouse capabilities.

**Acceptance Criteria:**

**Given** the Admin is logged into the WMS
**When** the Admin navigates to the User Management screen
**Then** they can view, create, edit, and deactivate user accounts
**And** they can assign fundamental roles (Super Admin (Seeded only), Admin, Warehouse Staff) to each account with optional `customPermissions` overrides.
**And** the Database schema utilizes a `custom_permissions` String array (nullable), utilizing a graceful fallback to code-configured Roles if the value is null.
**And** the NestJS backend utilizes a custom `@RequirePermissions()` Guard that intercepts the JWT, fetches `session:user_data:{userId}` from Redis, and validates the permission set instantly.
**And** any update to user accounts triggers an explicit Redis cache invalidation for that specific user ensuring immediate access revocation.
**And** Application Use Cases unconditionally block any API requests attempting to manipulate (Update Role, Delete) the core `SUPER_ADMIN` account.

### Story 1.3: Global System Configurations

As an Admin,
I want to save and retrieve global system configuration variables,
So that the entire system uses standardized metric terminology and Excel export templates.

**Acceptance Criteria:**

**Given** the Admin has authenticated successfully
**When** the Admin submits updates to system-wide settings
**Then** the configurations are safely stored in PostgreSQL and structured into Redis cache
**And** subsequent retrievals execute rapidly without hitting the database.

## Epic 2: Commercial Catalog (Products & Customers)

Đội ngũ Sale/Quản lý có thể khai báo một chuỗi Master Data sẵn sàng tham chiến: các cuộn hàng với đầy đủ thông số kích thước vật lý và tệp khách hàng gắn chặt với tỷ lệ chiết khấu riêng biệt.

### Story 2.1: Product Catalog & Physical Metric Definition

As a Manager,
I want to create and manage Product Categories with specific physical baseline dimensions,
So that the intelligent Unit Engine knows the core width, length, and weight for each item.

**Acceptance Criteria:**

**Given** the Manager is on the Product Management module
**When** they create a new Product Category
**Then** they must rigidly specify the fundamental `numeric` values for its baseline length (meters) and unit density
**And** the database restricts arbitrary string/float conversions, storing it safely as `NUMERIC(15,3)`.

### Story 2.2: Customer Registry & Dynamic Pricing Rules

As a Manager,
I want to securely maintain a registry of Customers and their tiered discount policies,
So that sales staff can generate Goods Issues without having to memorize manual rules.

**Acceptance Criteria:**

**Given** the Manager is operating the Customer Module
**When** they register a Customer, they can link standard pricing profiles (e.g., Tier 1, 15% discount)
**Then** the system commits this linkage securely to the backend
**And** updates the Redis cache so that the Pricing Engine can auto-evaluate ticket lines.

## Epic 3: Inbound Operations & Stock Generation

Thủ kho có thể khai báo các chuyến hàng đến một cách mượt mà. Hệ thống sẽ tự cấp mã phiếu, quy đổi thông minh mét/kg và ghi lại những dòng log tồn kho "bất biến" đầu tiên.

### Story 3.1: Draft Goods Receipt & Intelligent Ticket Generation

As a Warehouse Staff member,
I want to initiate a new Goods Receipt for incoming trucks,
So that I can draft an inbound manifest incrementally.

**Acceptance Criteria:**

**Given** the staff clicks "New Receipt"
**When** the API receives the request
**Then** the backend securely generates a chronologically unique Ticket ID (e.g., `PN-0001`)
**And** provides an empty draft object holding lines for data entry.

### Story 3.2: Real-time Unit Conversion Engine Execution

As a Warehouse Staff member,
I want the system to automatically calculate alternative dimension metrics (m², kg) as I type the length of a roll,
So that I avoid human calculation errors on the warehouse floor.

**Acceptance Criteria:**

**Given** the staff is adding a line item to a Goods Receipt
**When** they select a Product and input physical metrics like "100 meters"
**Then** the pure Unit Conversion Engine safely parses the dimensions
**And** computes the exact equivalent representations based on the central catalog values.

### Story 3.3: Confirm Goods Receipt & Trigger Immutable Audit Trail

As a Warehouse Staff member,
I want to explicitly "Confirm" a finalized Goods Receipt,
So that the items officially enter our live inventory calculation pool.

**Acceptance Criteria:**

**Given** a completed, draft-status Goods Receipt
**When** the user hits Confirm
**Then** the system transitions the ticket state to Immutable (locked from edits)
**And** updates the active `Stock Balance` tables globally
**And** generates an Insert-Only `StockMovement` logging trace recording who did what and when.

## Epic 4: Outbound Operations & Intelligent Pricing

Nhân viên chỉ trong thời gian ngắn tạo được "Phiếu Xuất" có khả năng đo đếm chính xác giá trị hóa đơn, và tuyệt đối bị cản lại nếu xuất hàng vượt quá mức tồn kho.

### Story 4.1: Draft Goods Issue & Automatic Client Pricing

As a Sales Operator,
I want to select a target Customer for my newly drafted Goods Issue,
So that the system knows exactly which discount matrix to implement against the items I add.

**Acceptance Criteria:**

**Given** the operator is on the Outbound/Issue ticketing screen
**When** they select a target Customer entity
**Then** the distinct Pricing Evaluator engine immediately evaluates and locks the baseline rate for this ticket
**And** subsequent roll additions auto-fill the field "Price" based on the background discount computation.

### Story 4.2: Enforce Hard-Limit Negative Stock Blocks

As an Inventory Manager,
I want the system to aggressively prevent staff from overdrafting the warehouse,
So that we never mistakenly sell a roll that has physically already left the building.

**Acceptance Criteria:**

**Given** the user is drafting an Outbound Ticket
**When** they attempt to add an item whose required length/quantity surpasses backend active inventory balances
**Then** the API explicitly blocks the transaction via a `400 Negative Stock` Exception code
**And** the Flutter Dio interceptor beautifully catches it to flash a red invalidation banner UI safely.

### Story 4.3: Confirm Goods Issue Transaction

As a Sales Operator,
I want to "Confirm" the outbound order,
So that the final shipment is subtracted from live inventory ledgers safely.

**Acceptance Criteria:**

**Given** a valid outbound draft containing no negative-stock exceptions
**When** Confirm is submitted
**Then** the balance is definitively decremented and locked
**And** an immutable Audit trail records the outbound deduction trace.

## Epic 5: Internal Operations & Audit Roll-backs

Thủ kho có thể "xẻ mảnh" chia tách kích cỡ từng cuộn hàng trên hệ thống. Kế toán/Admin có thể "Quay ngược thời gian" hồi phục số liệu kho an toàn nếu chốt nhầm phiếu.

### Story 5.1: Execute Physical Roll Split Workflow

As a Warehouse Staff member,
I want to split an existing Master Roll into smaller physical distributions,
So that we can handle fractional deliveries accurately.

**Acceptance Criteria:**

**Given** a verified Master Roll exists in stock (e.g., 200m)
**When** the user authors a Split Operation demanding 50m
**Then** the core logic gracefully deducts 50m from parent ID length, keeping 150m intact
**And** creates a brand-new child Inventory record representing the torn 50m
**And** logs out the exact parent-child derivation relationship in the active trail.

### Story 5.2: Admin Level Transaction Void & Inventory Reversal

As an Admin,
I want to Void (Cancel) a mistakenly Confirmed ticket,
So that faulty logistics operations can be safely reversed without corrupting the historical database.

**Acceptance Criteria:**

**Given** a previously confirmed Ticket
**When** the Admin issues a Void Override action
**Then** the active inventory balances are inverted strictly backward
**And** an additional corrective "Undo-Trace" is appended to the `StockMovement` sequence (data is never hard-deleted).

## Epic 6: Reporting Intelligence & Document Export

Quản lý có thể trực tiếp xuất biểu Excel chuẩn form kế toán và in file Ticket PDF hóa đơn cho tài xế giao nhận mà không cần thao tác manual.

### Story US-601: High-Volume Global Live Inventory Rendering

As an Analyst,
I want to monitor thousands of warehouse lines instantly without experiencing UI lag,
So that I can scan inventory effectively during heavy load periods.

**Acceptance Criteria:**

**Given** over 10,000 active inventory item lines
**When** the user accesses the Inventory module
**Then** the Flutter grid rendering framework (`pluto_grid`) displays the data losslessly
**And** filters columns instantly maintaining 60FPS scrolling capacity.

### Story US-602: Universal Historical Audit Trail Querying

As an Administrator,
I want to search and review the raw, immutable Audit Trail,
So that I can deduce exactly which employee modified particular lines over time.

**Acceptance Criteria:**

**Given** the Admin is on the Audit Analytics form
**When** they execute a strict data range search or Product ID constraint
**Then** the read-only append sequences are queried efficiently from the database
**And** rendered to show exact timestamps and actions.

### Story US-603: Native PDF Document Export Execution (Backend Mediated)

As a logistical runner,
I want to immediately download and print a finalized Outbound Ticket format,
So that I can hand a polished receipt out to transportation.

**Acceptance Criteria:**

**Given** a confirmed Ticket URL mapped with ID
**When** the user requests the PDF format
**Then** the NestJS backend's Puppeteer engine seamlessly renders the structured HTML template into a binary blob
**And** fires it safely over the network for the Desktop Client to pop open externally via browser/FoxIt.

### Story US-604: Legacy Accounting Format Excel Export

As the Lead Accountant,
I want to pull the end-of-month live Data block exactly aligned to my historical spreadsheets,
So that I can bypass any VLOOKUP reconciliation effort securely.

**Acceptance Criteria:**

**Given** a Time Parameter context (e.g., March 2026)
**When** the accountant triggers the mass Export
**Then** the backend ExcelJS service intercepts the inventory state matrix
**And** dynamically injects the numbers purely matching the provided legacy columns (Inputs, Outputs, End-Balances), delivering the file downward securely.
